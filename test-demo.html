Authentication Flow Demonstration

┌─────────────────────────────────────────────────────────────┐ │ SCENARIO 1: Valid Login (user1@example.com → company-a) │ └─────────────────────────────────────────────────────────────┘ 1. Frontend: User selects "company-a" and enters credentials ↓ 2. Cognito: Validates password ✓ ↓ 3. Post Auth Lambda: - Checks if user1@example.com belongs to company-a - Result: ✓ User belongs to tenant - Adds custom:tenant_id = "company-a" to token ↓ 4. Token Generated: { "email": "user1@example.com", "custom:tenant_id": "company-a" ← Injected claim } ↓ 5. Backend: Reads custom:tenant_id from token - Serves company-a data - Result: ✓ Success ┌─────────────────────────────────────────────────────────────┐ │ SCENARIO 2: Invalid Login (user1@example.com → company-b) │ └─────────────────────────────────────────────────────────────┘ 1. Frontend: User selects "company-b" and enters credentials ↓ 2. Cognito: Validates password ✓ ↓ 3. Post Auth Lambda: - Checks if user1@example.com belongs to company-b - Result: ✗ User does NOT belong to tenant - Throws error: "Not authorized for tenant" ↓ 4. Cognito: Rejects authentication ✗ ↓ 5. Frontend: Receives error - No token generated - Result: ✗ Authentication Failed
